# Local deletion receipt prerequisite

No deployment or gateway change has been authorized/performed. The receipt-only status request uses no user JWT because the account may already be deleted. Target deployment must route it to the handler (for example a separately reviewed verify_jwt=false setting); authenticated deletion still verifies the user server-side, while status-only recovery requires the exact random receipt whose SHA256 was stored before deletion. Verify this endpoint/gateway mode on the isolated backend before deployment. Do not change project-wide JWT verification.

Budget order: the handler resolves the caller's JWT before spending any budget. An authenticated request charges the caller's own `delete_account` bucket (6/min/user, 120/min global); a receipt-only request charges the separate `delete_account_status` pool keyed by the receipt UUID (migration `20260912120000_security_prelaunch`), so unauthenticated probing cannot exhaust the deletion budget. Deploy the migration before or together with this function version.

Only server-verified user_not_found plus its exact 404, or an already-confirmed receipt, is treated as deletion. Generic 401/404/transport failure is not proof. Receipts contain a user UUID and a random nonce hash, no profile/text/store credentials. The client keeps the nonce with its existing app-local account state until cleanup; never log it. Proposed operational receipt retention is seven days with an unscheduled bounded prune function; owner/privacy review is still required. Account deletion does not cancel App Store subscriptions.

Sign in with Apple revocation (Guideline 5.1.1(v)): when the authenticated caller has an `apple` identity, the handler first exchanges the optional `apple_authorization_code` from the request body for a refresh token and revokes it at `appleid.apple.com/auth/revoke` (`_shared/apple-revocation.ts`), using the `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_CLIENT_ID` and `APPLE_PRIVATE_KEY` function secrets (see `docs/SETUP_REQUIRED.md` § 5b). The step is best effort: any failure is logged as a single `apple_revocation_failed` line (reason only, never the code or token) and `deleteUser` still runs, which cascades to `auth.identities`. Requests without a code (Android, cancelled Apple sheet, older clients) are accepted unchanged.
