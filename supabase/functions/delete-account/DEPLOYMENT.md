# Local deletion receipt prerequisite

No deployment or gateway change has been authorized/performed. The receipt-only status request uses no user JWT because the account may already be deleted. Target deployment must route it to the handler (for example a separately reviewed verify_jwt=false setting); authenticated deletion still verifies the user server-side, while status-only recovery requires the exact random receipt whose SHA256 was stored before deletion. Verify this endpoint/gateway mode on the isolated backend before deployment. Do not change project-wide JWT verification.

Only server-verified user_not_found plus its exact 404, or an already-confirmed receipt, is treated as deletion. Generic 401/404/transport failure is not proof. Receipts contain a user UUID and a random nonce hash, no profile/text/store credentials. The client keeps the nonce with its existing app-local account state until cleanup; never log it. Proposed operational receipt retention is seven days with an unscheduled bounded prune function; owner/privacy review is still required. Account deletion does not cancel App Store subscriptions. Provider/Apple revocation and policy applicability remain unverified release prerequisites.
