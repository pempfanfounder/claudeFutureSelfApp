# Authorized autonomous continuation

Apply when workflow.json execution_policy.mode is authorized_autonomous with its real founder receipt in DECISIONS. APP-AUTONOMY-003 changes coordination only. Preserve saved stage/cycle/candidate, completed evidence, approvals, expiry/exhaustion and paused native recovery. Historical handoffs requesting a new chat or another Continue at routine boundaries are superseded; their operational restrictions and evidence remain binding. Setup/status-only requests never start work, and a founder pause/stop always stops safely.

## One coordinator, distinct implementation and QA

The current coordinating task remains sole checkpoint writer and integrator. APP-AUTONOMY-003 supersedes the manual coordination preference APP-MANUAL-001; resume the current saved stage without resetting it. For each subsequent session, including every implementation and independent QA cycle, automatically create a NEW VISIBLE Codex task and send its scoped handoff. The coordinator waits for results, reviews evidence, checkpoints, and dispatches the next already-authorized session without a founder Continue. Use fresh QA tasks, not in-chat subagents or an implementer's task. Do not reuse a completed execution task for a later session. Do not create another coordinator.

The coordinator provides absolute canonical/source/evidence paths, exact candidate identity, stage/repair scope, permissions and remaining shared budgets. Default task checkouts do not replace the preserved source worktree or canonical state. Execution tasks must not reset/reinitialize progress, write canonical checkpoints, dispatch other tasks or claim control of the coordinator. They return artifacts and findings. At Stage4 completion the coordinator reviews/freezes source/build/config identity, test receipts and limits before creating the fresh Stage5 task. A QA task receives a minimal requirements/reproduction/candidate brief, not the implementation conversation or reasoning; it makes no product fixes. Source review is not independent QA. One console operator at a time, explicitly assigned. All tasks share the existing limits; task creation replenishes nothing.

## Checkpoint then continue

1. Save evidence and update applicable STATE/DECISIONS/WORK/QA/RELEASE, archive prior JSON, increment revision and update NEXT from the same checkpoint. Check durable writes/mirrors and run workflow.py check. Preserve the previous checkpoint on conflict; never reset progress.
2. For a completed stage set next_stage normally. Do not merge implementation and QA into an unrecorded step. Verify the next stage's prerequisites, exact candidate, approval scope/expiry and remaining budget before transitioning. Do not replenish/reset an allowance by changing stage, agent, task or cycle. A new bounded run may be defined only where the existing authority already permits it; retain consumption of prior finite scopes.
3. If authorized, automatically dispatch the next session as a new visible task, wait for its result in the coordinating task, and give concise progress updates. No founder Continue is needed. Fresh independent QA returns pass/fail/blocked evidence; an already-authorized ordinary repair routes Stage5→4→fresh5 with a checkpoint on every edge. A new/out-of-scope repair requires a concrete gate.
4. Continue useful independent authorized work while a prerequisite is missing. Stop when no such work remains, a required decision/approval is reached, or repeated failure warrants reassessment. Save the precise blocker, attempted resolution, preserved state and one next action. An access denial is not permission to bypass controls. Required physical/native/store evidence remains blocked when unavailable.

## Gates and failure bounds

G1/G2/G3/G5, production settings/config/deployment, costs/paid resources, credentials, legal/owner declarations, Apple upload/submission/public release and any specific later action keep their existing explicit authority requirements. Bare Continue, broad autonomy or elapsed time never approves them. Preserve the native recovery pause and exhausted Sentry send budget. After a real gate is answered unambiguously, checkpoint the exact receipt, revalidate scope and resume its authorized work without a separate routine Continue.

Track failure evidence by finding and candidate. If the same finding fails two consecutive substantive repair→independent-retest attempts without resolution, stop and present the root-cause uncertainty and a concrete reassessment. Stricter existing attempt/time/request/cost caps take precedence. Do not reset this count with a new stage/task or relabel the same defect. A new distinct finding or a corrected test-harness error is recorded honestly and does not automatically count as another failed product repair. A passing retest closes that finding; it does not waive unrelated gaps.

External waiting is an access/prerequisite blocker. APP-AUTONOMY-003 authorizes the existing five-minute heartbeat to inspect saved workflow/task status and coordinate admitted work. It grants no additional third-party polling, SQL/native/provider calls or promise of completion. Follow local/AUTO_CONTINUE.md and its duplicate-prevention control record. Keep existing bounded status-check authority; if no authorized finite wait/check can advance work, checkpoint awaiting_external and explain the dependency. On task interruption preserve active operations, ownership and stop conditions, then resume from that checkpoint when execution returns. Clear ownership when no work is active.

## Scheduled coordination

The existing five-minute heartbeat targets the current coordinator identified in workflow.json and local/auto-continue/control.json. One coordinator owns dispatch/checkpoints; workers never dispatch successors. A heartbeat is permission to inspect saved task/workflow status, not to consume additional service budgets. Resume an unfinished saved stage from preserved results; do not restart a completed worker or silently advance to QA before review/freeze. Routine boundary checkpoints remain mandatory. Keep gate/access blockers quiet while unchanged and report only meaningful progress, completion, failure or required founder action. No additional automation is authorized.
