# Session 1 — Discovery and founder decisions

Read START_HERE, MASTER_CONTEXT and WORKFLOW first, along with the saved checkpoint and relevant live records. This prompt does not authorize itself: the dispatcher must have admitted this stage. Use actual available tools and current founder scope. Checkpoint evidence at each stage boundary. Then follow the saved execution policy and reference/AUTONOMOUS_CONTINUATION.md: continue already-authorized work in the coordinating task, or stop for the specific unmet gate/blocker. A routine boundary does not require another founder message in autonomous mode.

## Goal and authority
Establish what is really present, what the founder wants to ship, and how later inspection/testing can occur safely. This is not a security audit, design pass or implementation session. Default authority is local reads, safe scoped read-only dashboard inspection and workflow records. No app launch, native build, dependency install, app tests, production change or code fix in this stage.

## Inspect first
Use the setup receipt as an orientation, not current truth. Record local root, full SHA, branch, dirty/untracked state, lockfile/package-manager evidence and relevant ignored-work presence without disclosing secret values. Preserve divergences from public main. Do not pull/reset/stash/clean or invent a pristine state.

Read reference/PROJECT_BRIEF and REPOSITORY_MAP. Reconcile manifest/config, actual routes/features, design system, auth, content, onboarding, purchases, notifications/widgets, Supabase migrations/functions, current tests and historical setup/release docs at architectural depth. Locate changed paths. Inventory actual dependencies beyond the named services. Old docs/launch artifacts, if present, are historical inputs: import useful decisions with provenance and re-confirm material authority; never move/delete them or treat old approval as current.

Trace environment loading and startup side effects statically. Compare EAS profiles, environment override mechanisms and presence/classes of required local values without printing them. Record environment overlap or uncertainty without resolving it by key replacement. Native folders are generated/ignored; their presence/absence is not a build result.

## Capabilities and service access
Identify available local shell, Git, Python/Node/package manager, Xcode path/runtime/device capability, browser/Computer Use, relevant connectors and specialist tools. Do not install or enable anything globally. For an unavailable capability, record what is missing and the specific later task affected; continue independent discovery. The founder must not be asked to configure a whole tool stack prematurely.

Where actually authorized, read service identity, plan and configuration for Supabase, RevenueCat, Expo/EAS, Apple, Sentry, PostHog and discovered email/push/API services. Avoid customer data and unrelated browser/account content. An inaccessible dashboard is unknown. Do not call an app endpoint merely to check connectivity: that may create work/cost.

## Interview adaptively
Ask at most three unresolved high-value questions per round after inspecting sources. Start with scope/variants/content promise/commercial behavior if still uncertain. Provide your recommendation and its tradeoff; let the founder decide. Resolve exact storefronts/ages only as needed. Do not repeat supplied EU/U.S. or premium-motion goals. Do not make them recall inspectable configuration.

Separate product decisions from implementation/financial authorization. Capture keep/defer/disable distinctions so abandoned experiments do not expand QA indefinitely. Inspect the current package catalog before asking which offerings are intended. Confirm acceptable test exposure, designated test identities, available iPhone access and any nonnegotiable visual/content features.

Propose a safe G1 envelope: permitted environments and operations, installation/build side effects, local/sandbox test identities, explicit request/concurrency/duration/spend limits and no production load. No paid resource creation by implication. A zero-service-traffic local/mock option may allow early work, but does not count as integration proof.

Request **G1: launch scope and safe audit/prototype test envelope** with a concise exact approval response. When approved, record the receipt, mark Session1 complete, set next_stage=2 and checkpoint. Continue only under the saved autonomous policy and approved next-stage envelope; otherwise wait at the boundary.
