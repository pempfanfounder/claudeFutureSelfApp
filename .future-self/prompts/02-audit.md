## Billing abuse and integration wiring
For every service, map trigger → downstream work/fan-out/retry → billed unit → current plan/included use → quota/throttle/enforceable limit → monitoring/stop control. Distinguish budget alerts from hard ceilings and vendor plan charges from request counts. Use actual dashboard/official evidence and date assumptions. Estimate ordinary-user and abuse exposure with explicit arithmetic and uncertainty; do not claim a precise cap if no global enforceable control exists.

Test direct API calls with ordinary authorized test-user tokens as well as UI paths, per-user and global limits, many identities, duplicate/out-of-order events and failures. Bound every scenario by the approved request/concurrency/duration/spend envelope and test-account allowlist. Reproduction in a faithful isolated environment is preferred; never prove an issue by harming production. Record theoretical, realistically reachable, reproduced, protected or unverified status.

Build one wiring matrix covering client, backend, dashboard, generated-native/build and end-to-end evidence for Supabase, RevenueCat, Apple, Expo push/EAS, Sentry, analytics, email and anything else found. “Key present” is not “wired and tested.” Check current official platform/privacy requirements separately from legal/owner facts.
